# C4 model

Job Tracker's architecture at the first three [C4](https://c4model.com) levels: system context, containers, and the components inside the API. The code level is left out — the source is the reference. For request-level flows see [`architecture.md`](./architecture.md) and [`uml.md`](./uml.md).

## Level 1 — System context

Who uses Job Tracker and which outside systems it depends on.

```mermaid
C4Context
    title System context — Job Tracker

    Person(user, "Job seeker", "Tracks applications, target companies and interviews")

    System(jt, "Job Tracker", "Web app, API and browser extension for tracking a job search")

    System_Ext(oauth, "Google / GitHub", "OAuth sign-in")
    System_Ext(groq, "Groq", "Hosted LLM, openai/gpt-oss-120b")
    System_Ext(tavily, "Tavily", "Web search API")
    System_Ext(sites, "Company websites", "Public homepage and /about pages")
    System_Ext(resend, "Resend", "Transactional email")

    Rel(user, jt, "Tracks jobs, companies, interviews", "HTTPS")
    Rel(jt, oauth, "Signs users in", "OAuth 2.0")
    Rel(jt, groq, "Parses postings, extracts company facts, summarizes timelines", "HTTPS")
    Rel(jt, tavily, "Searches for company and posting info", "HTTPS")
    Rel(jt, sites, "Fetches page text", "HTTPS")
    Rel(jt, resend, "Sends reminders and digests", "HTTPS")
    Rel(resend, user, "Emails")

    UpdateLayoutConfig($c4ShapeInRow="3", $c4BoundaryInRow="1")
```

## Level 2 — Containers

The separately deployed or data-holding parts of Job Tracker. Deployment detail (VM, Docker Compose, Vercel) is in [`architecture.md`](./architecture.md#deployment-topology).

```mermaid
C4Container
    title Containers — Job Tracker

    Person(user, "Job seeker")

    System_Boundary(jt, "Job Tracker") {
        Container(web, "Web app", "Next.js, React, TanStack Query — Vercel", "All UI: jobs board, companies, interviews, profile, admin")
        Container(ext, "Browser extension", "Chrome MV3", "Imports the posting in the open tab")
        Container(proxy, "Reverse proxy", "Caddy 2", "TLS termination and compression")
        Container(api, "API", "NestJS, Prisma, BullMQ", "REST API, hourly and daily crons, background workers")
        ContainerDb(db, "Database", "PostgreSQL on Neon", "Store of record for all app data")
        ContainerQueue(redis, "Queue store", "Redis 7", "BullMQ jobs, OAuth one-time codes")
        ContainerDb(files, "File storage", "Oracle Object Storage, S3 API", "Resume PDFs")
    }

    System_Ext(oauth, "Google / GitHub", "OAuth")
    System_Ext(ai, "Groq and Tavily", "LLM and web search")
    System_Ext(resend, "Resend", "Email")

    Rel(user, web, "Uses", "HTTPS")
    Rel(user, ext, "Clicks Import")
    Rel(web, proxy, "JSON API calls, Bearer JWT + refresh cookie", "HTTPS")
    Rel(ext, proxy, "PAT exchange, parse and create job", "HTTPS")
    Rel(proxy, api, "Forwards", "HTTP :3001")
    Rel(api, db, "Reads and writes", "Prisma, SQL/TLS")
    Rel(api, redis, "Enqueues and consumes jobs", "RESP")
    Rel(api, files, "Stores, deletes, presigns", "S3 API")
    Rel(web, files, "Downloads resume via presigned URL", "HTTPS")
    Rel(api, oauth, "Redirects and fetches profile", "OAuth 2.0")
    Rel(api, ai, "Prompts and searches", "HTTPS")
    Rel(api, resend, "Sends email", "HTTPS")

    UpdateLayoutConfig($c4ShapeInRow="4", $c4BoundaryInRow="1")
```

## Level 3 — Components of the API

NestJS modules inside the API container. Every feature module reads and writes Postgres through the global `PrismaService`; those arrows are left out to keep the diagram readable.

```mermaid
C4Component
    title Components — API (NestJS)

    Container(web, "Web app", "Next.js")
    Container(ext, "Browser extension", "Chrome MV3")

    Container_Boundary(api, "API") {
        Component(auth, "Auth", "AuthModule, Passport guards", "Login, JWT + refresh rotation, OAuth, PAT exchange")
        Component(jobs, "Jobs", "JobsModule", "Jobs, JobEvent log, stats, posting parser")
        Component(companies, "Companies", "CompaniesModule", "Companies, CSV import, contacts, enrichment trigger")
        Component(rounds, "Interview rounds", "InterviewRoundsModule", "Rounds, round prep")
        Component(resumes, "Resumes", "ResumesModule", "PDF upload and download URLs")
        Component(workers, "Background workers", "BullMQ processors", "Company enrichment, timeline summary, notifications")
        Component(sched, "Schedulers", "@nestjs/schedule crons", "Hourly reminders and digests, daily token cleanup")
        Component(llm, "Enrichment services", "LlmService, SearchService, WebFetchService", "Groq, Tavily and page fetch clients")
        Component(storage, "Storage", "StorageService", "Local disk or Oracle driver")
    }

    ContainerQueue(redis, "Queue store", "Redis 7")
    ContainerDb(files, "File storage", "Oracle Object Storage")
    System_Ext(ai, "Groq and Tavily", "LLM and web search")
    System_Ext(resend, "Resend", "Email")

    Rel(web, auth, "Signs in", "JSON/HTTPS")
    Rel(web, jobs, "Manages jobs", "JSON/HTTPS")
    Rel(ext, jobs, "Parses and creates jobs", "JSON/HTTPS")
    Rel(jobs, llm, "Parses postings")
    Rel(rounds, llm, "Generates round prep")
    Rel(jobs, redis, "Enqueues enrichment and summaries")
    Rel(companies, redis, "Enqueues enrichment")
    Rel(sched, redis, "Enqueues reminders and digests")
    Rel(redis, workers, "Delivers jobs")
    Rel(workers, llm, "Extracts and summarizes")
    Rel(llm, ai, "Calls", "HTTPS")
    Rel(workers, resend, "Sends email", "HTTPS")
    Rel(resumes, storage, "Stores PDFs")
    Rel(storage, files, "S3 API")

    UpdateLayoutConfig($c4ShapeInRow="3", $c4BoundaryInRow="1")
```

Contacts belong to `CompaniesModule` in this diagram for brevity; in code they are their own `ContactsModule`, owned through a parent job or company. Tokens, users, admin and health modules are omitted.
